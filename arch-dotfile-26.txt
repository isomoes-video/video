中文标题：2026 Arch Linux 配置进化
English Title: My 2026 Arch Linux Dotfiles — Agent First

本期是 UP 主对自己 Arch Linux dot file（配置文件）在 2026 年的一次整体回顾与更新。距离上一次系统性地介绍 Linux 桌面下所用的软件已经过去大约一年，这个 dotfile 仓库也积累了约一年、360 多次 commit。视频顺着仓库的演进脉络，讲清楚相较于旧版环境，2026 年究竟做了哪些改变，以及为什么这样改。

UP 主先回顾了 2025 年的"折腾期"：刚上手 Arch 时，在桌面定制上投入了大量精力，用 Hyprland、fish、waybar 把桌面环境做得高度个性化，还尝试了全键盘驱动的 qutebrowser，以及 River 等窗口管理器、Firefox 配合 vim 式按键插件，让浏览器里也能用上类 vim 操作。随后重心逐渐从桌面微调转向"为 Agent 搭建运行环境"：开始配置 Claude Code，并把后端模型替换成 DeepSeek、Kimi、智谱 BigModel 等国产模型——这正赶上去年八九月这些模型集中发布、掀起热潮的时间点，从性价比与模型能力两个角度做了不少试验。他也试过一套可复现性极强、以"配置文件即运行环境"为核心思想的系统（类 NixOS 的打包方式），但发现它在二次开发小工具、对系统本身做微调时并不方便，最终在 2026 年初回到了 Arch 的打包版本。

进入 2026，绝大部分时间都花在"让 AI coding 更好、方式更多"上。年初 GPT 模型价格极低，UP 主一度切换到 OpenCode，并自建 CLI 代理服务、组建账号池来积累足够的 token，从而尝试 multi-agent。在这个过程中他意识到：Agent 最理想的运行环境其实是 Linux。苹果推出了原生运行的 Linux 容器镜像，微软在 2026 年的 Build 上也提到用轻量级镜像让 Linux 命令原生跑在 Windows / macOS 上——这些大厂趋势从侧面印证了 Agent 在 Linux 下能力最强。由此他建议 2026 年新入学的大一学生，不妨直接上手 Linux + AI Agent，体验会远超旧系统。到了 2026 年 5 月，由于 GPT 风控等级上升、性价比下降，他最终回归 Claude Code，订阅也随其新推出的多 Agent 能力（ultracode、agent views 等并行编排功能）和新模型一起回到了 Claude。

视频的后半段落在理念与现状上。UP 主总结道：2025 年是不断尝试新编辑器、浏览器、窗口管理器、把常用工具调得更美观以提升生产力的一年；而 2026 是 Agent 当道的一年，过去靠 IDE 和各种工具人工完成的事，如今大多可以交给 Agent 托管。于是配置思路转为"能简化就简化"，给 Agent 一个最纯净的 runtime——软件包数量虽从 163 增到 190（多为特定任务的依赖），但实际常用的小工具一直在减少；仓库结构也更规范，拆成多个子仓库以实现按需加载。最核心的改变是：系统服务的对象从"人"变成了"Agent"。以前系统是为人写代码（用 IDE、编译、图形界面）服务，现在越来越多的配置遵循 agent first，目标有二：一是让 Agent 能高自由度地调用任意工具，二是把系统变成监督 Agent 的 super views。配套理念则是 less is more——尽量少折腾，换取更统一的控制、一致性、肌肉记忆，慢慢积累成壁垒。

落到具体实践，UP 主越来越倾向把自建小工具做成基于 web 技术栈的服务（web 前端 + 后端），可用命令行或 Docker 启动，方便跨平台迁移甚至部署到云端，也便于做监督。他展示了两个自建服务：做 RSS 阅读的 iReader，以及用来审阅、审计 Agent 运行的 agent views——后者能看出哪些工具常出错、哪个工具耗时最长，对优化下一次 Agent 运行很有指导意义。视频里这篇博客本身就是由 Agent 生成的：一个 prompt 跑了 33 分钟，中间还动态编排了一个 workflow（主线程阻塞等待、收到通知后异步恢复）；这次 session 主 Agent 约 $2.34、含子 Agent 实际约 $5.53，但因为用的是订阅计划，折算下来大约只花了一块五人民币。最后 UP 主总览了当前在用的工具：桌面与顶栏、kitty 终端、zsh、单一编辑器、git 加 lazygit、OBS 录屏与脚本剪辑工具、作监督用的 Chrome，以及已迁移到 docker compose 的 iReader 与 agent views，外加一套在浏览器、终端、应用间统一通用的 vim 式键位。
