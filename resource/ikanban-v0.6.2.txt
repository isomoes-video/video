中文标题：AI 工具越改越累？iKanban 回到 OpenCode V2，少维护、多做事
English Title: Spending Too Much Time Maintaining AI Tools? iKanban Returns to OpenCode V2 to Get More Done

为什么 iKanban 在尝试 DeepSeek Harness 之后，又回到了 OpenCode？这期视频结合 v0.5.1 → v0.6.2 的迁移文档，分享一次关于开发精力和使用体验的取舍：把更多时间放在组织多个 AI Agent 完成实际任务上，让已有的运行时承担底层执行工作。

我们先回顾离开 DeepSeek Harness 的两个主要原因。高度自由的提示词、工具和上下文定制，带来了反复验证工作流效果的时间与模型调用成本；插件和 Web 通讯接口持续演进，也让二次开发、兼容性适配和上游同步变得更费精力。对于当前阶段的 iKanban，我们更希望先复用已有能力，再通过 Skill、MCP 和交互层改进满足日常需求。

随后介绍 OpenCode V2 吸引我们的几个方面：多会话与多 Agent 并行、工作空间与会话切换、更容易复用的共享桌面 / Web 前端和服务 API，以及按需发现工具、通过 Code Mode 脚本组合调用的方式。视频也讨论了 AGENTS.md 等指令变化通过追加更新保留上下文前缀的思路，以及这些机制为何有机会减少上下文开销、请求次数和缓存失效；具体收益仍取决于任务与模型服务的实际使用情况。

最后回顾 iKanban 从 DSH 阶段到接入 OpenCode V2、再到采用共享前端的迁移过程，介绍 v0.6.2 的键盘交互、主题等调整，以及后续围绕已有 API 改善多 Agent 管理体验的方向。
