中文标题：自建QQ群机器人：管群与快讯
English Title: Building a QQ Group Bot: Auto-Recall Ads and Daily AI News Digest

这期视频完整讲解如何自建一个 QQ 群机器人，并复盘了这套方案一年间的技术演进：为什么去年（2025）的旧实现要被推倒，今年又如何借官方开放的新能力重做一遍。

动机很朴素——作者手里有几个需要维护的 QQ 群，作为管理员想做一个机器人帮忙自动化处理群内事务。去年的旧方案基于 NapCat：在容器里跑一个不带 GUI、最精简的 QQ 客户端，把客户端运行时里加载的相关函数 hook 出来，再通过 WebSocket 这类通用传输手段对接到一个专门的消息处理 bot 上，整套链路等价于程序化地操作一台真实的 QQ 客户端。这是因为当时 QQ 官方对个人开发者限制很高，群聊消息接口并不开放，只支持频道场景，只能这样"曲线救国"。这套方案能跑通，但有两个硬伤：一是本身并不合规，二是挂载在上面的 QQ 号有被风控甚至封号的风险。

今年的转机来自 AI Agent 生态的爆发。随着各类平台都在把 Agent 能力接入现有聊天软件，QQ 官方顺势做了适配，正式向个人开发者开放了群聊消息 API。于是作者把技术栈切换到官方方案：直接使用官方 SDK，并选用在官方 SDK 之上做了二次封装的 qq-official-bot 这类 library，在其之上封装出自己的机器人，合规与账号安全的问题也随之解决。

重构后的机器人做了两个核心功能。第一个是群管理自动撤回：针对群里其他 bot 常发的广告和敏感信息，用关键词加正则的模式匹配来识别，一旦命中广告特征或指定句式，就自动把消息撤回（recall）；这要求机器人在群里拥有管理员权限。第二个是 AI 快讯，源自作者每天读 AI 资讯却难免漏看的习惯，索性交给机器人代劳：从平常订阅的 RSS 资讯源上游拉取内容，按近一天的时间窗口过滤，并且只取文章的摘要部分而非全文，避免喂给大模型时上下文过大；随后调用 DeepSeek 等大模型对截取内容做二次总结，每天通过定时任务把当天热点快讯推送到群里，遇到感兴趣的新闻再点链接看原文。

实现细节上，当天请求到的资讯和总结结果都会缓存进本地 SQLite 数据库，既避免重复调用大模型、控制成本，也方便日后回看——想查某天的新闻直接查库就能拿到当天总结好的热点，无需重新生成；由于只服务单个群，直接落库即可，若并发更高再换成 Redis。

部署非常简单：项目已打包成 Docker 镜像，用 docker run 或 docker compose 就能部署到自己的服务器，各项功能都通过环境变量来开启和配置。视频最后，作者欢迎有类似需求的朋友试用，也欢迎提交 issue 和 PR，并感谢观看。
