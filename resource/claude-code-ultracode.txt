中文标题：Claude Code 动态工作流详解
English Title: Claude Code Dynamic Workflow (Ultracode)

本期视频介绍 Claude Code 随 Opus 4.8 同步推出的动态工作流（dynamic workflow），也就是把思考等级调到最高档 ultra code 后才会启用的功能。视频首先对比了上一期讲过的 cloud agents（cloud views）：两者都做并行任务，但 cloud agents 基于 git worktree，靠文件系统级隔离，在不同独立 workspace 路径下并行修改，因此几百个分支之间通信困难、难以避免冲突。而动态工作流的核心区别在于，它能在同一个 workspace、同一套文件系统、同一个仓库里同时运行几十甚至上百个 agent，由父 agent 统一调度，确保多个子 agent 修改相同文件时不发生冲突，适合几百个文件的大规模软件迁移这类场景。

随后作者用一个实例演示：把原本分为服务端与客户端两个 package 的项目合并为一个包。在 ultra coder 模式下，Claude Code 会自动创建一个 workflow，先生成 steps.md（需要做哪些步骤）和 spec.md（提前约束哪些规则重要、哪些不重要），再据此生成分阶段的 subagent。这次合并任务被拆成两个阶段，每个阶段又分多个子 agent 并行运行，把单个 workspace 的并行能力拉满。这相当于把以前需要手动建 to do.md、手动开 6 个窗口做 verify 的流程自动化，因此复杂任务可以连续运行几个小时甚至一两天。本次合并任务共耗时 17 分钟。官方博客的例子是把约 75 万行代码迁移到 Rust，仅用 11 天，一天可处理上万行，远超普通程序员一天 1000 行的产量。

最后作者分析了用量：在 Opus 4.8 加 ultra coder 下，本次任务约花掉 5 小时额度的 9%、周额度约 1%，按比例推算 10% 的 5 小时额度约等于 1.2% 周额度（近期周额度还上调了 50%）。17 分钟用 10% 推算，连续使用约 170 分钟（约 2 小时）。Max 5 叉只够跑 1~2 小时的复杂任务，若想 5 小时连续运行动态工作流，可能需要冲到最高档 Max 20 叉，具体也取决于 workflow 下有多少个 subagent。总体而言，动态工作流相较此前的 agent views 在并行度上有很大提升。
