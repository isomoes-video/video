中文标题：AI 能干活了，人该做什么？用 iKanban 把意图表达与结果审阅串起来
English Title: AI Can Do the Work—What Should You Do? Connect Clear Intent with Result Review Using iKanban

当 AI Agent 已经能读项目、改文件和运行工具，我们还需要怎样的工作环境？这期结合日常使用的 iKanban 与 OpenCode，分享从传统 IDE 走向 ADE 的变化：把执行交给 Agent，把人的注意力放在表达意图和审阅结果上，而不是继续围绕手动编辑组织工作。

视频回顾了从 Neovim、Linux 和 IDE 探索到当前工作流的过程，说明 iKanban 前端与 OpenCode 执行后端的分工，并通过项目、会话和 worktree 展示需求提出、Agent 执行、反馈修改的循环。随后讨论语音输入怎样降低表达成本，怎样从变更摘要切入审阅，以及为什么代码之外的论文 PDF 等产物需要适合自身领域的预览方式。摘要用于分配审阅注意力，不应被当作正确性证明；高风险修改仍需检查具体实现。

当任务与多 Agent 循环运行得更久，手机和桌面连接同一后端就成为实际需求。视频介绍 systemd、FRP 与 HTTPS 的部署思路，并强调远程访问必须先考虑认证和安全，不能把端口连通等同于安全可用。最后将这些变化放回模型 API、Agent runtime、项目与领域资源、人的交互环境四层结构，讨论继续优化 iKanban，以及结合 AI4Paper 的论文检索、写作和绘图资源探索领域工具的方向。领域化 ADE 是后续探索，不代表当前已有完整论文产品或插件生态。
